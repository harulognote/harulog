## 2. 기존 서버에서 적용하는 순서 — 중요

사용자 구분이 없던 기존 자료를 각 회원의 공간으로 분리하므로 **ownership 마이그레이션이 필요합니다.** 프로그램 시작 시 자동 실행하지 않습니다. 기존 자료는 지정한 회원에게만 귀속합니다. 최초 관리자 본인의 기존 개인자료라면 회원 ID 1을 지정하면 됩니다.

1. 기존 HaruLog를 종료하고 **프로그램 폴더 전체 및 MariaDB 전체 백업**을 별도로 만듭니다.
2. 기존 경로를 유지하여 새 소스를 적용합니다. `.env`, `.venv`, `uploads`, `harulog_ai_link.json`(있다면), cloudflared/TOOLS를 보존합니다. 압축파일의 uploads는 과거 원본이므로 기존 폴더에 덮어쓸 필요가 없습니다. 실제 .env와 DB는 배포본에 없습니다.
3. 기존 BAT/MD를 직접 백업 폴더로 옮기고 새 Run_harulog.bat 및 README.md만 사용합니다. 프로그램이 구파일을 삭제하지 않습니다. 제거 대상 예: HaruLog_Launcher, START_SERVER, Setup_harulog, Migrate_DB, Configure_External_Access, Configure_AI_Link, Run_harulog_Local/FixedTunnel/Cloudflare 및 버전별 Run 배치, 이전 MANUAL/CHANGELOG/VERIFICATION/VERSION_COMPARISON 문서. 기존 run_harulog.sh/configure_ai_link.py는 더 이상 사용하지 않습니다.
4. **Run_harulog.bat을 실행합니다.** 기존 핵심 DB가 정상이라면 새 회원·권한 테이블과 없는 pets만 프로그램 내부에서 생성합니다. 기존 업무 테이블을 ALTER하거나 기존 자료를 이관하지 않습니다.
5. 서버 콘솔의 **최초 관리자 설정 링크**를 열거나, 로그인 화면에 **최초 관리자 설정 코드**를 입력합니다. 로컬 링크는 `http://127.0.0.1:5000/login#setup=...`이며 외부 모드에서는 해당 Cloudflare 주소의 설정 링크도 출력됩니다. 실제 포트/코드는 콘솔 값을 사용합니다. 아이디와 8자 이상 비밀번호로 최초 관리자를 등록합니다. 회원 ID는 1입니다. 공개 주소만 알고 코드를 모르면 등록할 수 없습니다. 링크/코드를 공유하지 마세요.
6. 로그인 후 자료 분리 준비 안내가 나오는 것은 정상입니다. 이때 관리자 메뉴·멤버 관리·로그인 계정 변경은 가능하지만, 기존 업무 API와 첨부파일은 차단합니다. **서버를 Ctrl+C로 종료합니다.**
7. HaruLog 폴더의 CMD에서 아래 명령으로 **계획만 조회**합니다. 다른 회원에게 귀속해야 하면 그 회원을 먼저 가입·승인한 뒤 실제 회원 ID를 지정합니다.

```bat
.venv\Scripts\python.exe manage.py migrate ownership --owner-id 1
```

8. DB 백업과 서버 중단, 귀속 회원이 올바른지 확인한 뒤에만 아래 명령을 직접 실행합니다.

```bat
.venv\Scripts\python.exe manage.py migrate ownership --owner-id 1 --apply --backup-confirmed
```

9. 완료 후 Run_harulog.bat을 다시 실행합니다. 지정한 계정에서 기존 자료가 보이는지 확인합니다. 이후 다른 사용자는 로그인 화면의 회원가입으로 가입하고, 관리자가 승인합니다. 신규 사용자 공간에는 다른 회원의 기존 자료가 표시되지 않습니다.

되돌릴 때는 소스와 DB를 같은 백업 시점으로 함께 복원해야 합니다. 사용자 구분이 없는 예전 소스만 다시 실행하면 안 됩니다.

`--backup-confirmed`는 실제 백업을 대신 만들지 않습니다. 마이그레이션은 열/키 변경과 자료 귀속을 수행하며 MariaDB DDL은 자동 커밋될 수 있습니다. 중간 실패 시 전체 롤백을 보장하지 않습니다. 완료 표시는 모든 단계 성공 후에만 기록하므로 중간 실패 상태에서는 업무자료 접근을 계속 차단합니다. 원인을 확인한 뒤 같은 소유자로 재시도하거나 백업으로 복원해야 합니다. 기존 owner_id가 있는 행은 덮어쓰지 않습니다.

## 3. ownership 작업의 실제 범위

- 10개 업무 테이블: daily_logs, study_videos, vocab_list, study_dictations, golf_rounds, expense_invoices, personal_profile, golf_contacts, utility_records, pets.
- 각 테이블에 없는 owner_id를 추가하고 소유자가 없는 기존 행만 지정한 활성 회원에게 귀속합니다. 이후 owner_id는 NOT NULL이며 조회용 인덱스를 추가합니다.
- personal_profile의 기본키를 (owner_id,id)로 변경합니다. 사용자별 기본정보 1번 행을 독립 저장합니다.
- 공과금 청구월과 펫 혈통등록번호의 UNIQUE를 사용자별 복합키로 변경합니다.
- 기존 레코드의 본문/사진을 삭제하거나 초기화하지 않습니다. 모든 회원에게 기존 자료를 공개하지 않습니다.
- 앱의 SQL 연결에서 소유자를 강제하며, 조회·수정·삭제·통계·검색·영상 단어 연결·펫 부모 관계에도 적용합니다. 첨부 경로도 소유 레코드가 있어야 접근할 수 있습니다. 관리자는 본인의 owner_id로 동일하게 제한됩니다.
- 분리 완료 표식과 10개 테이블의 owner_id 존재를 확인한 경우에만 업무 API/첨부에 접근할 수 있습니다. 구조/인덱스의 임의 변경까지 자동 복구하지는 않습니다.

## 4. 관리자 메뉴와 회원가입

로그인한 활성 admin에게만 **전체메뉴 → 관리자**가 표시됩니다. 일반 사용자는 메뉴를 강제로 표시하거나 API 주소를 알아도 서버에서 거부됩니다.

- 아이디/이름 검색, 100명 단위 목록과 이전/다음 페이지.
- 조회·수정: 아이디, 이름, admin/user 역할, pending/active/suspended/deleted 상태.
- 승인: pending → active로 변경하여 저장.
- 정지·삭제·복구: 상태 변경으로 처리하며 사용자 ID와 자료는 유지.
- 비밀번호 재설정: 새 비밀번호를 입력할 때만 변경. 기존 비밀번호 조회는 불가.
- 모든 변경/삭제에는 관리자 자신의 현재 비밀번호 입력이 필요.
- 관리 기록에는 작업자·대상·변경 전후의 멤버 정보와 재설정 여부를 저장합니다. 비밀번호나 해시는 기록하지 않습니다. 멤버 변경과 기록 저장은 같은 트랜잭션입니다.

본인 아이디/비밀번호는 **개인설정 → 로그인 계정 관리**에서 현재 비밀번호를 확인한 후 변경합니다. 개인설정의 역할 값으로 관리자 권한을 얻을 수 없습니다. 비밀번호 변경과 멤버 관리 변경은 대상 세션을 무효화합니다. 프로그램 재시작 시 다시 로그인하며 세션은 8시간 기준입니다.

## 5. 실행·접속·설치 원칙

일반 배치는 폴더/UTF-8과 기존 .venv Python 호출만 담당합니다. 프로그램 시작 때 패키지 설치, .venv 생성, .env 쓰기, 계정 입력, 기존 테이블 ALTER, 자료 변환/귀속을 자동 실행하지 않습니다. 신규 독립 기능 테이블만 프로그램 내부에서 생성합니다: pets, app_members, app_system, app_admin_audit. 기존 단일 계정용 app_accounts가 있더라도 자동 변환·삭제하지 않습니다. v2.8.5 미사용이면 해당 테이블 자체가 없어도 됩니다.

접속 방식은 `.env`의 HARULOG_CONNECTION으로 지정합니다. 배치를 추가하지 않습니다.

| 값 | 동작 |
|---|---|
| quick | 기본값. 임시 Cloudflare 주소 + 프로그램 로그인 |
| fixed | 별도 고정 Tunnel용 서버 + 프로그램 로그인 |
| local | 내부망 서버 + 프로그램 로그인 |

```ini
HARULOG_CONNECTION=quick
APP_PORT=5000
CLOUDFLARED_PATH=C:/Users/vagrant/TOOLS/cloudflared.exe
```

cloudflared는 내부 TOOLS → 상위 TOOLS → 프로그램 폴더 → PATH 순으로 찾으며 경로를 직접 지정할 수 있습니다. 바이너리는 포함하지 않았고 자동 설치하지 않습니다. 별도 외부 계정/Basic 인증은 없습니다. 예전 HARULOG_ACCESS_* 값은 사용하지 않습니다.

외부 모드는 loopback에만 바인딩합니다. 모바일에서 MOBILE URL을 열어 프로그램에 로그인합니다. Quick Tunnel 주소는 재실행 때 바뀌며 상시 운영에는 고정 Tunnel이 적합합니다. fixed에서는 같은 Windows의 커넥터 서비스 주소를 http://127.0.0.1:5000으로 지정하고 실제 HARULOG_PUBLIC_URL을 설정합니다. 다른 APP_PORT를 쓴다면 맞춰야 합니다. 다른 프로그램의 터널은 변경하지 않습니다. local에서는 APP_HOST/APP_PORT를 사용합니다.

세션 쿠키 HttpOnly/SameSite, 외부 HTTPS의 Secure, 변경 요청 CSRF 검사, 로그인·가입 시도 제한, no-store를 적용했습니다. 최초 관리자 등록은 서버 콘솔의 일회용 코드와 CSRF를 검사합니다. 코드 유무를 접속 주소로 대신 판단하지 않습니다. runtime에는 주소/로그 등 실행 정보를 기록하고 정리합니다.

기존 정상 환경에 **새 패키지를 추가할 필요는 없습니다.** requirements.txt는 이전과 같습니다. Python 3.10 이상과 기존 MariaDB가 필요합니다. 환경이 부족할 때만 아래 명령을 직접 실행하세요.

```bat
py -3 manage.py install
```

위 명령은 계획만 표시합니다. 실제 설치를 결정했을 때만 다음을 실행합니다.

```bat
py -3 manage.py install --apply
```

설치 명령은 없는 .venv 생성과 패키지 설치만 하며 DB/설정을 생성하지 않습니다. 기존 환경을 자동 삭제하지 않습니다. .env가 없으면 기존 설정을 복원하거나 .env.example을 직접 복사해 DB 값을 입력합니다. 실제 DB가 없으면 별도 DB 생성/복원이 필요합니다.

## 6. 그 밖의 수동 관리

핵심 테이블/컬럼이 부족하다는 안내가 있는 경우에만 schema 계획을 확인합니다. source에 지원된 컬럼 추가만 처리하며 임의의 타입·인덱스 차이를 자동 수리하지 않습니다. DB 백업 후 필요한 작업만 직접 적용합니다.

```bat
.venv\Scripts\python.exe manage.py migrate schema
.venv\Scripts\python.exe manage.py migrate schema --apply --backup-confirmed
```

펫 기능을 사용하지 않으셨다면 cats-to-pets 이관은 필요 없습니다. 과거 자료가 실제로 있는 경우에만 계획을 확인합니다. pets가 비어 있을 때만 복사하며 원본 cats는 보존합니다. ownership 이후에는 기존 귀속 회원 ID로 복사합니다. languages는 과거 한글 언어명만 코드로 바꾸는 별도 선택 작업입니다. 일반 실행에서 수행하지 않습니다.

```bat
.venv\Scripts\python.exe manage.py migrate cats-to-pets
.venv\Scripts\python.exe manage.py migrate languages
```

위 두 작업도 필요한 경우에만 --apply --backup-confirmed를 직접 추가합니다. 자동으로 일괄 적용하지 않습니다. 서버를 중단한 상태에서 수행하세요.

AI 연결은 필요한 경우에만 아래 명령을 직접 실행합니다. 키 값이 아닌 기존 설정 파일 위치만 연결합니다.

```bat
.venv\Scripts\python.exe manage.py link-ai
```

OCR/AI는 선택 기능이며 설정이 없으면 해당 기능의 제한만 안내합니다. Tesseract 설치·경로 설정은 별도로 진행합니다. 자동 설치·다운로드는 없습니다.

## 종료와 터미널 창

Ctrl+C는 현재 HaruLog의 웹 서버를 중단하고, 이번 실행에서 Popen으로 생성한 Quick Tunnel의 개별 프로세스만 정리합니다. 같은 cloudflared.exe 파일을 사용하더라도 다른 PID로 실행된 CenterHub 등 다른 프로그램의 터널은 건드리지 않습니다. fixed 모드의 별도 터널 서비스도 HaruLog가 만든 프로세스가 아니므로 종료하지 않습니다.

정상 종료에서는 배치 끝의 pause를 제거했습니다. BAT를 더블클릭해 열린 창은 배치 종료 후 닫히고, 이미 열려 있던 CMD/터미널에서 실행했다면 명령 프롬프트로 돌아갑니다. 기존 터미널 자체를 강제로 닫지는 않습니다. 오류가 났을 때만 내용을 확인할 수 있도록 pause로 대기합니다. Windows CMD 자체에서 배치 종료 확인 질문이 나오는 경우에는 해당 질문에 답해야 합니다.

로그인 페이지 하단은 HaruLog v2.9.13이며 `/api/auth/status`에도 version이 표시됩니다. 새 소스를 교체했는데 이전 화면/메시지가 나오면 이전 프로세스의 종료 여부, 실행 폴더 및 포트가 같은지 확인하세요. `pet_records`와 `pet_lineage`는 신규 독립 테이블로만 생성되며 기존 테이블의 추가 마이그레이션은 없습니다. 이미 완료한 ownership은 다시 실행하지 마세요.

## 7. 검증과 한계

Python 회귀 156건, JavaScript 회귀 31건 및 전체 문법 검사를 통과했습니다. 두 개 로그인 세션과 실제 Flask 업무 경로를 통해 관리자/일반 사용자 자료 조회 분리, 다른 사용자 사진 404, 타인 기록 수정/삭제 거부, 클라이언트 owner_id 무시를 확인했습니다. SQL 분리·조인/OR/통계·쓰기·스키마 준비·마이그레이션 완료 표식·승인/정지/삭제·관리 기록 롤백·역할 접근 제어를 검사했습니다. 일반 사용자의 관리자 메뉴 숨김도 검사했습니다.

업무 SQL은 SQLite 대역, 회원/권한 DB는 테스트 대역으로 검사했습니다. 실제 Waitress의 로그인 전후 API·로그아웃·Quick/fixed 실행·종료 정리도 확인했으며 Cloudflare 프로세스는 대역입니다. 운영 MariaDB DDL/잠금 동시성, Windows CMD, 실제 Cloudflare와 모바일 화면은 확인하지 못했습니다. 운영 DB에는 연결하거나 변경하지 않았습니다. 반드시 백업과 계획 확인 후 적용하세요.
